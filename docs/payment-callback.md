# 支付成功回调与库存更新

自建验收样例，包含预设缺陷，仅用于工作台审查演示，不是生产支付服务。

## 场景与约定

- 小店最初有 10 件商品，一张订单买 2 件。处理支付成功后，订单变为 paid，库存应剩 8 件。
- 支付平台可能重复投递同一条成功通知。同一个订单、同一个 transactionId 的重复通知必须幂等：保持原来的订单与库存，不再扣减，也不因重试而报库存不足。
- 不同订单的正常支付应分别扣减库存；无效订单、空流水号、库存不足的首次支付应拒绝。
- 函数返回新状态，不能修改传入的原对象。

接口：从 core/src/index.ts 导入 applyPayment(state, notification)。金额、验签和网络接入不在本例范围内；视为通知已通过上游认证。本例只要求顺序重放下的内存状态幂等，不声称解决跨进程并发或数据库事务。

## 验证

仓库根目录 npm test，或在 projects/ts-monorepo 下 npm test；Node.js 24+，不需要外部依赖。现有测试覆盖普通支付、不同订单、非法输入和状态不可变性。维护者需要独立核对重复投递约定及测试覆盖，不能只看测试是否通过。
