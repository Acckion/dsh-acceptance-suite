# 场景 01：收件箱、筛选与批量分诊

## 前置

- 已运行 `npm run seed` 且 `npm run status` 全绿
- 插件已接入本仓库，模型已配置

## 步骤与预期

| # | 操作 | 预期 |
|---|---|---|
| 1 | 打开收件箱 Issue 页签 | 11 条种子 Issue 全部出现，未分诊项标记正确 |
| 2 | 依次切换筛选：所有开放 / 尚未分诊 / 高优先级 / 疑似重复 / 已关闭 | 高优先级仅 ISS-HIGH；已关闭仅 ISS-CLOSED；疑似重复在分诊后出现 DUP 对 |
| 3 | 搜索框输入 `add` | ISS-BUG、ISS-DUP-A、ISS-DUP-B 同时命中 |
| 4 | 勾选全部开放 Issue，执行智能分诊（批量） | 每批 ≤20、并发可见；逐项产出分类/优先级/置信度/缺失信息/建议标签；失败逐项报告 |
| 5 | 查看 ISS-BUG 分诊结果 | 分类 bug；建议指向 `projects/node-ts-app`；缺失信息合理（无则为空） |
| 6 | 查看 ISS-NEEDSINFO 分诊结果 | 分类 bug 或 question；明确列出缺失信息（复现步骤/环境/版本等），不虚构根因 |
| 7 | 查看 DUP-A/B 分诊结果 | 各自给出"疑似重复"建议及共享证据（引用交叉评论 #编号），不自动关闭 |
| 8 | 查看 ISS-FEATURE / ISS-QUESTION / ISS-MAINTENANCE 分类 | 分别为 feature / question / maintenance |
| 9 | 查看任务（Tasks）页 | 快速分诊默认隐藏；处理链按事项聚合，状态分组正确 |
