# 场景 08：多仓库、自动化与等待回复同步

## 前置

- 已运行 `npm run seed:secondary`（创建 `<owner>/dsh-acceptance-secondary` + 2 条 Issue）
- 主仓库种子完整

## 多仓库接入与切换

| # | 操作 | 预期 |
|---|---|---|
| 1 | 在接入仓库输入两行：主仓 + secondary 的 `owner/repo` | 每行一个；重复自动合并；失败逐项显示 |
| 2 | 切换当前仓库到 secondary | 收件箱只剩 secondary 的 2 条 Issue；勾选项/详情/发布预览被清空 |
| 3 | 切回主仓 | 记住上次选择；主仓收件箱与任务恢复 |
| 4 | 分别在两仓派发任务 | 队列、审核、克隆按仓库隔离；活动记录共享 |
| 5 | 同步全部 | 两仓各自刷新；失败互不影响 |

## 自动化分诊

| # | 操作 | 预期 |
|---|---|---|
| 6 | 设置中开启自动分诊（默认关闭） | 仅新版本 Issue 触发；跳过等待/暂缓事项 |
| 7 | 运行 `npm run seed:followup` | 创建 ISS-NEW（深色模式对比度）；开启自动化后应在下次轮询被自动轻量分诊 |
| 8 | 关闭自动化 | 不再自动触发 |

## 等待与追问同步

| # | 操作 | 预期 |
|---|---|---|
| 9 | 对 ISS-WAIT 分诊/调查中记录追问，状态进入等待用户 | 等待记录持久化；不自动发评论 |
| 10 | 运行 `npm run seed:followup`（发布维护者回复） | 向 ISS-WAIT 追加补充复现记录评论 |
| 11 | 再次同步 | 检测到新回复，提示"待重新评估"；不自动重跑模型；旧输入标记过期 |

## 队列与并发

| # | 操作 | 预期 |
|---|---|---|
| 12 | 批量勾选多仓事项派发 | 按仓库轮转调度；同事项串行；并发上限（默认 2）生效 |
| 13 | 取消运行中任务 | 取消保留已产生产物；worktree 保留供检查 |
